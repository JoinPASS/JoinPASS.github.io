# Change Spec: Homepage Expansion and Internal Access Plan

## Status

Accepted

## Scope

Refine the bilingual PASS website information architecture to better match the
intended professional study-group experience.

This change adds:

- A richer bilingual homepage that expands the community-planning content
  directly on the front page.
- A more polished homepage layout with sectioned operating information rather
  than a minimal hero plus document links.
- A protected internal access-planning page under the Supabase-gated internal
  area.
- A protected internal access-planning page that exists without visible
  browseable links in the normal site UI.

This change removes the need for a separate public page dedicated to access
planning while preserving a complete public ground-rules page.

## Non-Goals

- This change does not alter Supabase database schema or RLS policies.
- This change does not integrate with Google Calendar or Google Drive APIs.
- This change does not add new admin capabilities beyond the current whitelist
  management UI.
- This change does not move private non-web files into the repository.

## User-Visible Behavior

Public visitors:

- Land on a bilingual homepage that already explains the community structure,
  meeting rhythm, participation expectations, internal sharing norms, and
  public summary cadence.
- Can still open a complete public ground-rules page.
- Can understand the main study-group operating model directly from the
  homepage.

Authorized internal members:

- Continue to see protected Calendar and Documents links.
- Can open a dedicated internal access-planning page after authentication when
  given the protected URL directly.

## Data, Auth, or Deployment Impact

Auth and deployment behavior remain the same:

- Public pages remain statically generated by Hugo.
- Internal pages remain gated in the browser through Supabase Auth and
  whitelist authorization.
- The new internal access-planning page uses the existing authentication flow.

## Acceptance Criteria

- The public homepage in both languages expands the community-planning content
  in a professional, well-structured layout.
- The homepage presents substantial community-planning content directly.
- A complete public ground-rules page still exists in both languages.
- Access planning is no longer published as a public documentation page.
- A protected internal access-planning page exists in both languages.
- No visible public-facing or ordinary browsing UI links expose the
  access-planning page.
- Local Hugo build succeeds.

## Verification Notes

Implementation should be verified with:

- `hugo build --gc --minify`
- `node --check assets/js/joinpass-internal.js`
- Visual inspection of `/zh-tw/`, `/en/`, `/zh-tw/internal/`, and
  `/zh-tw/internal/access/`
