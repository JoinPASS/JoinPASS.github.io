# Change Spec: Traditional Chinese and English i18n

## Status

Accepted

## Scope

Add internationalization as a durable project requirement. The public website
must support both Traditional Chinese and English, and future Hugo
implementation work must use a multilingual content and configuration structure.

## Non-Goals

- This change does not scaffold the Hugo project.
- This change does not translate the study group content yet.
- This change does not configure the final Vercel build settings.
- This change does not implement authentication for private pages.

## User-Visible Behavior

Visitors should be able to browse the public site in Traditional Chinese or
English. Public navigation, page titles, core content, and language switching
should feel intentional and professional in both languages.

Traditional Chinese is the primary audience language. English must remain a
first-class supported language rather than an afterthought.

## Data, Auth, or Deployment Impact

No database, authentication, or deployment behavior changes are introduced by
this requirement by itself.

Future implementation work must account for language-aware routing and content
paths in the Hugo configuration. Private-page authorization must remain
language-independent so access control is not duplicated per locale.

## Acceptance Criteria

- The project spec records Traditional Chinese and English as required
  languages.
- The project spec requires a multilingual Hugo content/configuration model.
- The project spec requires visible language switching on public pages.
- The project spec requires future content work to identify bilingual or
  language-specific scope.
